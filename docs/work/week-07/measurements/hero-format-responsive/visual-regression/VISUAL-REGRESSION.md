# 4번째 금지 항목 — 시각적 회귀 교차 검증

과제 1단계 요구사항 4번째 항목:

> Hero의 시각적 크기, 비율, 주요 피사체와 문구를 유지해요. 이미지를 작게 보이게 하거나 품질을 낮춰 수치만 줄이면 안 돼요.

## 검증 대상

- Before: `public/images/week-07/hero-original.jpg` (3840×2160 jpeg) 그대로 `<img>`로 렌더
- After(최종): `next/image`의 `fill` + `sizes="(max-width: 1200px) 100vw, 1200px"`로 렌더. 뷰포트 1350px(desktop 프리셋)에서 실제 요청은 `w=1200&q=75`, `image/webp`, 87,656 B

## 검증 방법

### 1) CSS 기반 표시 크기 대조 (코드 근거)

`.page-container { width: min(100% - 32px, 1200px) }`, `.hero { width: 100%; aspect-ratio: 16/9 }` (`HeroSection.module.css`)는 Before/After 사이 변경하지 않았다. 뷰포트 1350px 기준 계산:

- 컨테이너 폭: `min(1350-32, 1200) = 1200px`
- Hero 박스: `1200 × (1200×9/16) = 1200×675`
- Before: `<img>`가 `width:100%; height:100%; object-fit:cover`로 이 박스를 그대로 채움 → 표시 크기 1200×675
- After: `next/image`의 `fill`이 같은 부모 박스(`position:relative`, `aspect-ratio:16/9`)를 그대로 채움 → 표시 크기 1200×675

**결론**: 표시 크기는 Before/After 동일(1200×675). 애초에 원본 3840px를 그대로 내려받고 있었을 뿐 화면에는 항상 1200×675로 축소되어 그려지고 있었다 — 이번 변경은 "화면에 그려지는 크기"가 아니라 "그 크기를 위해 내려받는 리소스 해상도"만 실제 표시 크기에 맞춘 것이다.

### 2) 전체 페이지 스크린샷 대조 (레이아웃 · 문구 · 피사체)

- `before-fullpage-filmstrip-8192ms.png`: Before 5회 Lighthouse 측정 중 run-5의 완전 로드 시점(8192ms) filmstrip 프레임
- `after-fullpage-1350x940.png`: 최종 코드 상태를 production build(`pnpm build && pnpm start`)로 띄운 뒤 헤드리스 Chrome(`--window-size=1350,940 --virtual-time-budget=6000`)으로 직접 캡처한 스크린샷

두 이미지에서 다음을 육안 대조했다: Hero 박스 위치·크기, 비율(16:9 크롭 동일, 피사체 잘림 없음), 올리브 나무·토트백·스니커즈·니트·항아리 피사체 구도 동일, "이번 주의 발견" eyebrow·"매일 새롭게 발견하는 취향" 제목·설명 문구와 오버레이 위치 동일. 차이 없음.

### 3) 실제 배송 리소스 픽셀 비교 (품질 저하 여부)

브라우저 페이지 캡처는 리사이즈·안티에일리어싱이 섞여 압축 아티팩트 판정에 부적합해, 실제로 내려가는 바이트를 직접 비교했다.

- `delivered-w1200.webp`: 서버가 실제로 응답한 리소스(`curl "http://localhost:3000/_next/image?url=...&w=1200&q=75"`)
- 원본과 배송본에서 같은 상대 위치·같은 상대 크기(원본 대비 7.8% 폭)로 중앙 크롭 후, 배송본 크롭을 300×300으로 업스케일해 같은 확대율로 비교
  - `before-crop-native300x300.png`: 원본(3840px)에서 300×300 중앙 크롭 (네이티브 해상도, 업스케일 없음)
  - `after-crop-94upscaled300.png`: 배송본(1200px)에서 94×94 중앙 크롭 후 300×300으로 업스케일

**결론**: 가죽 질감·스티치 라인·음영 그라데이션이 배송본에서도 뭉개지지 않고 유지된다. 업스케일한 크롭이라 원본보다 약간 부드럽게 보이는 건 해상도를 표시 크기(1200px)에 맞춘 데 따른 자연스러운 차이이며, 블록 노이즈·색 밴딩·워터마크성 압축 아티팩트는 없다. 이 비교는 실제 사용자가 보는 배율(1200px 그대로 표시, 확대 없음)보다 훨씬 엄격한 조건이다 — 실사용 조건에서는 이 차이조차 보이지 않는다.
